# devgugga: AGENTS.md

GitHub profile README for `devgugga` (Gustavo Gomes). `CLAUDE.md` imports this file; keep rules here.

The page is three self-generated, animated SVGs composed in `README.md`. No third-party widgets: GitHub strips `<script>`, inline `style` attributes and external CSS from READMEs, but renders SVGs referenced by `<img>` and runs their CSS/SMIL animations.

| SVG | Generator | Regenerated by |
| --- | --- | --- |
| `portrait-ascii.svg` | `scripts/prep_photo.py` → `scripts/make_ascii_svg.py` | hand, only when the photo changes |
| `info-card.svg` | `scripts/make_info_card.py` (content lives in its `INFO` list) | hand, whenever the card text changes |
| `contrib-heatmap.svg` | `scripts/fetch_contributions.py` → `scripts/render_heatmap_svg.py` | CI every 6 hours (`.github/workflows/update-profile-art.yml`) |

## Setup

```bash
uv venv --python 3.11 .venv
uv pip install --python .venv/bin/python -r scripts/requirements.txt -r scripts/requirements-photo.txt
```

`requirements.txt` is what CI installs (heatmap only). `requirements-photo.txt` is local-only; rembg downloads a ~1 GB model to `~/.u2net` on first run. Python 3.14 lacks wheels for opencv/onnxruntime, hence 3.11.

## Changing things

- **Card text**: edit `INFO` in `scripts/make_info_card.py`, run it, commit `info-card.svg` with the script. The run prints `content ends at y=N`; N must stay below `H - 40` (about 586) or rows collide with the bottom prompt. To fit more rows, lower `LINE_H` or drop a row; the card height is fixed (next bullet).
- **Card height is coupled to the portrait**: `make_info_card.py` reads `portrait-ascii.svg`'s size so both panels render at the same height at the README widths (370 px and 490 px). Regenerate the portrait first, then the card. If you change those widths in `README.md`, change them in `match_portrait_height()` too.
- **Portrait**: the source photo is `source-photo.png` (git-ignored; the original is `~/Downloads/myself.png`). Run `prep_photo.py` then `make_ascii_svg.py`; tune `COLS`, `GAMMA`, `WHITE_FLOOR` in the latter. The script prints the ASCII to stdout: check the face is recognizable there before committing.
- **Heatmap**: CI owns it; edit the renderer, not the SVG. Levels are quantiles of non-zero days, like GitHub. Totals include private contributions only because the profile's *Contribution settings → Private contributions* is on; if the total drops to a public-only number, that setting was turned off (compare with the `<h2 id="js-contribution-activity-description">` in `https://github.com/users/devgugga/contributions`). Trigger a refresh with `gh workflow run "Update profile art" -R devgugga/devgugga`, then `git pull` (CI pushes a `[skip ci]` commit).

## SVG conventions

- Plain ASCII inside SVGs (write `Goias`, `&#8594;`): viewers render with their own system fonts, and emoji or accents fall back unpredictably. Font stack: `ui-monospace, SFMono-Regular, Menlo, Consolas, monospace`.
- Root `<svg>` carries `width`, `height` and `viewBox`.
- Animations play once and freeze. CSS reveals use `animation-fill-mode: both` with no standalone `opacity:0`, so a renderer that skips animation still shows the content.
- Every generator honors `STATIC=1` (final frame, no animation) for screenshots.
- Look: dark terminal windows (`#0d1117`, frame `#30363d`, traffic-light dots), accent teal `#00bfbf`, title bars in the form `gustavo@github: ~$ <command>`. README and card text are in English.

## Previewing

Before pushing a visual change, run `scripts/preview.sh [out.png]` and read the screenshot. It renders the README layout with every SVG frozen on its final frame (`STATIC=1`, headless `chromium`), then regenerates the animated SVGs that get committed. The portrait is blank in the preview unless `source-prepped.png` exists.

## Git

Push to `main` directly; this repo has no PR flow. The push triggers the workflow, which may add a heatmap commit on top, so `git pull` before the next change.
